WoWHead NPC Scraper

Collects World of Warcraft NPC names, stats, locations, and images from Wowhead's database and saves them as clean CSV datasets you can join, analyze, or load into other applications.

  • 20,400+NPC IDs indexed
  • 11expansions covered
  • 4datasets per expansion

1Overview

WoWHead NPC Scraper collects data on World of Warcraft NPCs (non-player characters) from Wowhead's NPC database and saves it as structured CSV datasets. It covers 11 expansions, from the original game through The War Within.

For each NPC ID, four Python scripts gather four kinds of data:

ScriptCollects
name_scraper.pyThe NPC's name
stats_scraper.pyLevel, classification, creature type, patch added, health
location_scraper.pyThe zones where the NPC appears
image_scraper.pyA screenshot URL

Wowhead builds these pages with JavaScript after they load, so a simple HTTP request returns them without the data. The scripts use Selenium to run a real headless Chrome browser, which waits for each page to finish rendering before reading it.

The repo holds about 20,400 NPC IDs across all 11 expansions. Data has been scraped so far for five of them: Base (Classic), The Burning Crusade, Wrath of the Lich King, Cataclysm, and Mists of Pandaria.

2Requirements and installation

To run the scraper you need Python 3, Google Chrome, and the Python packages Selenium and pandas.

  1. Clone the repo and move into it:
    bash
    git clone https://github.com/ChrisRaiz/WoWHead-NPC-Scraper.git
cd WoWHead-NPC-Scraper
  2. Create and activate a virtual environment:
    bash
    python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
  3. Install the dependencies:
    bash
    pip install selenium pandas
  4. Set up ChromeDriver. Selenium 4.6 and later finds or downloads a ChromeDriver that matches your installed Chrome, so normally no extra step is needed.
Original setup: the project was first built with ChromeDriver 114.0.5735.90 and the Google Chrome for Testing.app bundle placed in the project folder. That folder is already in .gitignore.

Run deactivate to leave the virtual environment when you're done.

3Usage

Each run scrapes one kind of data for one expansion. To choose the expansion, uncomment its csv_path block at the top of the script.

  1. Open the script for the data you want, for example scripts/stats_scraper.py.
  2. Comment out the active csv_path block (Base by default), then uncomment the block for the expansion you want.
  3. Run the script from inside the scripts folder:
    bash
    cd scripts
python3 stats_scraper.py
Each ID is printed as it's processed, and the output files are written once, after every ID has been visited. If you stop the script partway through, nothing is saved.

Building an ID list

The ID lists in Expansions/<code>/ID/ were exported from Wowhead's NPC search using these filters:

  1. Level: minimum 1. Set a maximum if the search returns more than 1,000 results.
  2. Added in patch: 1.1.2 or later.
  3. Added in expansion: the expansion you're collecting.
  4. Type: one creature type at a time (Beast, Humanoid, Undead, and so on). Copy the IDs into <code>_<Type>_IDs.csv.

Combine the per-type files into <code>_IDs.csv, which is the file the scripts read. It has a single ID column. The Wowpedia creature types page lists every type.

4Output

Each run writes up to three CSV files into that expansion's folder. Every file is keyed by the NPC's Wowhead ID, so the four data files can be joined on that column.

FolderFileContents
Data/<code>_NPC_<Kind>.csvIDs scraped successfully, with their data
Invalid/<code>_<Kind>_Invalid_IDs.csvIDs whose page loaded but didn't contain the expected data
Timeout/<code>_<Kind>_Timeout_IDs.csvIDs whose page didn't load in time. These are worth running again.

<Kind> is Names, Stats, Locations, or Images.

5How it works

All four scripts follow the same loop: open each NPC's page, wait for one element to appear, and sort the ID into one of three result lists.

Results are held in memory and written to disk only once the last ID is done. The scripts differ only in the element they wait for and how they clean it up:

ScriptElement it waits forCleanup
name_scraper.pyThe page <title>Removes the " - NPC - World of Warcraft" suffix
stats_scraper.pyThe infobox-inner-table quick-facts boxReads the Level, Classification, Type, Added in patch, and Health lines with regular expressions
location_scraper.pyThe og:description meta tag, then #locations, then heading-size-2 headingsRecords Unknown when the page says so. Keeps only letters and commas.
image_scraper.py<img> tags with class border from wow.zamimg.comSaves the first match's URL

All four scripts load pages at https://www.wowhead.com/npc=<ID>. If Wowhead redirects an NPC to another game version's database, location_scraper.py reloads the standard retail URL.

6Troubleshooting and limitations

ProblemCauseFix
Many IDs end up in Timeout/A slow connection, or Wowhead throttling repeated requestsRun the script again on just the timed-out IDs (see below).
A script crashes partway through and saves nothingOutput is written only after the loop finishes. name_scraper.py also has its WebDriverException handling commented out, so one browser error ends the run.Restore the commented try/except in name_scraper.py. Split very large ID lists into smaller runs.
Shadowlands output fails or lands in the wrong folderThe SL csv_path blocks leave SL/ out of the Timeout, Invalid, and Data pathsChange ./../Expansions/Timeout/... to ./../Expansions/SL/Timeout/..., and the same for Invalid and Data.
FileNotFoundError on startupThe script was run from outside scripts/, or the expansion's folder doesn't exist yetRun it from scripts/. Create the Data, Invalid, and Timeout folders for expansions that only have an ID folder.
Every ID comes back invalidWowhead changed its page layout, so the selectors no longer matchUpdate the selectors in the script (see How it works).
Chrome or ChromeDriver version errorThe driver doesn't match the installed ChromeUpgrade Selenium to 4.6 or later so it manages the driver itself.
Retrying timed-out IDs: point csv_path[0] at the Timeout file, which has the same ID column. Rename or back up the existing Data/ file first, because each run overwrites its output files instead of adding to them.
Speed: pages are loaded one at a time, and each wait allows 10 to 20 seconds, so a run of about 1,000 IDs can take hours. The scripts don't pause between requests. Keep runs reasonable so they don't put a heavy load on Wowhead.
